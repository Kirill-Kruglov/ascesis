## 0. Immutable project goal

Keep this goal visible at every step:

> Train an LLM / learner so that its world-model is **derived**, not merely generalized from internet-like data.

Current honest S-branch status:

> S4 implemented a tiny boundary-accounting / replay audit engine. It is not a semantic boundary generator, meaning engine, grounding system, substrate prototype, or learner-evidence system.

S4.1 exists because S4 passed artifact-level and mostly code-level review, but one gate-chain bug was found:

> `run_s4.py` self-certifies `s3_decision_confirmed: true` instead of reading and verifying `S3_decision.json`.

This must be repaired before demo packaging, postmortem, or any next S-step.

---

## 1. Why S4.1 exists

The S-branch depends on chained gates:

```text
S0 → S1 → S2 → B0 → S3 → S4
```

A downstream gate must not claim an upstream gate was passed unless it checks the upstream decision artifact.

S4 currently reports S3 confirmation, but the implementation does not actually verify the S3 decision file at runtime.

This creates a self-certification risk:

```text
S4 can report "S3 confirmed"
even if S3_decision.json is missing, corrupted, or failing.
```

S4.1 repairs that.

## 2. Gate question

Can S4 be patched so that:

```text
1. run_s4.py reads the expected S3_decision.json;
2. S4 pass is impossible if S3_decision.json is missing;
3. S4 pass is impossible if S3 decision is not S3-PASS-ADMISSIBLE-FOR-TINY-IMPLEMENTATION;
4. S4 report and decision JSON reflect the actual gate-chain check;
5. negative tests prove missing/failing S3 blocks S4 pass;
6. no new semantic/boundary-generator claim is introduced?
```

## 6. Required repair

### 6.1 Runtime S3 decision verification

Patch S4 so that it reads:

```text
experiments/S/S3_tiny_implementation_spec_for_boundary_accounting_replay_protocol/S3_decision.json
```

from the repository root or robustly relative to the S4 directory.

The checker must verify:

```json
{
  "decision": "S3-PASS-ADMISSIBLE-FOR-TINY-IMPLEMENTATION"
}
```

At minimum, S4 must fail if:

```text
S3_decision.json is missing
S3_decision.json is invalid JSON
S3_decision.json has no decision field
decision != S3-PASS-ADMISSIBLE-FOR-TINY-IMPLEMENTATION
```

### 6.2 Required function

Add or expose a function, preferably in `boundary_replay_engine.py` or `run_s4.py`:

```python
verify_upstream_s3_decision(path: str | Path) -> dict
```

It must return an audit object like:

```json
{
  "passed": true,
  "decision": "S3-PASS-ADMISSIBLE-FOR-TINY-IMPLEMENTATION",
  "path": "...",
  "errors": []
}
```

Failure object example:

```json
{
  "passed": false,
  "decision": null,
  "path": "...",
  "errors": ["S3_DECISION_MISSING"]
}
```

Allowed error codes:

```text
S3_DECISION_MISSING
S3_DECISION_INVALID_JSON
S3_DECISION_FIELD_MISSING
S3_DECISION_NOT_PASS
```

### 6.3 Decision integration

`S4_decision.json` must set:

```json
"s3_decision_confirmed": true
```

only if `verify_upstream_s3_decision` passes.

If upstream verification fails, S4 decision must not be:

```text
S4-PASS-TINY-IMPLEMENTATION-AUDIT-OK
```

It must be an appropriate failure, likely:

```text
S4-INCONCLUSIVE
```

or a S4.1-specific repair decision in the repair report.

### 6.4 Report integration

`S4_report.md` must not say “S3 decision was confirmed” unless the runtime check actually passed.

It must include a short “Gate-chain verification” line:

```text
S3 decision verification: pass/fail
S3 decision path: ...
S3 decision observed: ...
```

Expected:

```text

```

All G1–G5 must pass for S4.1 to pass.
