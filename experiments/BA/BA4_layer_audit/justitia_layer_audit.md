# BA4.1 Justitia Layer Audit

## 1. Executive Summary

This is a static/semantic audit of the current Justitia code. No Justitia source was modified and no new simulations were run.

**Definitely transition-relevant variables.** `Zone.wellness`, `Zone.productivity`, `Zone.recovery`, `Zone.migration_capacity`, `Zone.lineages`, `Lineage.mass`, `Lineage.strategy.*`, `Lineage.resource_stock`, `Lineage.mutation_var`, `Zone.containment_timer`, `Zone.last_aid`, `Zone.last_response`, `Zone.neighbor_delta`, accumulated harm/interception/extraction volumes, migration events, and `irreversible_failures` are transition-relevant or become transition-relevant through later policy/control reads.

**Policy/control-relevant variables.** `Obs.wellness`, `Obs.productivity`, `Obs.recovery`, `Obs.sag`, `Obs.last_aid`, `Obs.response_to_aid`, `Obs.neighbor_delta`, `Obs.resource_concentration`, `Obs.apparent_cooperation`, `Obs.response_diversity`, `containment_timer`, allocation scores, caps, and bad-consequence triggers are L2 policy/control variables. Governance/families/atlas wrappers add policy-visible mass shares and anti-HHI allocation scores.

**Observation-only or observation-first variables.** `Obs.strategy_diversity`, `Obs.migration_capacity`, and `Obs.global_welfare` are observation fields that are not directly scored by base policies. They become policy-relevant only under specific overrides or future policies. Observation variables must be separated from the underlying Zone/Lineage variables because `_delayed_obs` introduces history.

**Projection/abstraction-relevant variables.** Current 18.0 projection uses `mean_welfare` for the `a` coordinate and `resource_hhi` for the `c` coordinate. BA1/18.1 evidence shows the bounded doomed set is effectively U-only/current mean-welfare collapse, so `resource_hhi` is projection-visible but currently weak/inert for the final SAFE/DOOMED label. The real collapse definition uses `mean(zone_welfare) < 0.32`, `count(zone_welfare < 0.20) >= 4`, and `total_mass < 35`.

**Reporting-only variables.** `capture_index`, `permanence`, `strict_zero_capture`, `containment_cost`, `false_containment`, `delayed_consequence_true_harm_mi`, result classifications, Wilson intervals, boundary brackets, and most aggregate ratios are reporting/diagnostic unless a policy or transition function explicitly reads them.

**Variables probably wrongly grouped in previous MB taxonomy.** BA3 classified MB5 as `MB5_functionally_split`. `resource_hhi` was overloaded across policy-visible concentration, dynamics-visible HHI, projection-visible HHI, and reporting HHI. `capture_index` and exploit/cooperative shares are mostly L5 reporting, not transition mechanisms. `response_to_aid` and `neighbor_delta` are not just observations: they are delayed policy/control inputs. Delayed observations are a separate memory mechanism from the variables being observed.

## 2. Layer Definitions

- **L1 Dynamics:** variables/functions that directly update future Justitia state, including Zone/Lineage state, shocks, mass growth, mutation, migration, harm, aid interception, containment timers, and irreversible counters.
- **L2 Policy / Control:** variables/functions read by allocation, scoring, containment, audit, caps, throttles, or governance family wrappers.
- **L3 Observation:** variables written into `Obs` by `_observe` and selected by `_delayed_obs`; may be stale relative to current state.
- **L4 Projection / Abstraction:** variables used by the real collapse predicate or by the 18.0/18.1 shield projection/fidelity harness.
- **L5 Reporting / Diagnostic:** metrics used for summaries, validation gates, plots, studies, viability/permanence, or interpretive diagnostics but not read by transitions/policies unless explicitly wrapped.

## 6. Abstraction Eligibility List

### Eligible

- Zone.wellness/productivity/recovery and derived zone_welfare/mean_welfare
- total_mass and zone_mass summaries
- failed_zone_count using the real collapse spread clause
- minimum_zone_welfare as a compact spread witness candidate
- irreversible_failures if future requirement is explicitly about irreversible failure

### Conditional

- Obs.response_to_aid and Obs.neighbor_delta, only if false-safe witnesses require history/consequence channels
- Obs.resource_concentration / _resource_hhi_zone, only split by policy-visible vs dynamics-visible vs projection-visible role
- Lineage.mass aggregates such as exploit mass only after abstraction proof or witness need
- migration_capacity and containment_timer only if control-state reachability is modeled
- response_diversity/strategy_diversity only when the policy under study reads them or shocks depend on them

### Ineligible

- capture_index as a composite reporting metric
- permanence as a viability/reporting outcome
- exploitative_strategy_mass and cooperative_strategy_mass as reporting ratios by default

## 7. Layer Confusion Risks

- **resource_hhi:** This name spans L1, L2, L3, L4, and L5 depending on context. `_resource_hhi_zone` is read inside `_apply_zone_dynamics` for anti-concentration and growth, `_observe` exposes it as `Obs.resource_concentration`, `_trajectory_snapshot` reports zone-mass HHI, and 18.0 uses snapshot `resource_hhi` as projection `c`. These are not one mechanism.
- **capture_index:** A composite L5 diagnostic used for permanence/viability reporting. It is not read by base transition or policy functions. Treating it as a transition mechanism would be a layer error.
- **reporting ratios:** `exploitative_strategy_mass`, `cooperative_strategy_mass`, `max_lineage_share`, and capture components are diagnostics unless an override/policy explicitly reads analogous ratios.
- **policy-visible concentration:** `Obs.resource_concentration` affects `_bad_consequence` and containment policies. It must be separated from reporting HHI.
- **delayed observations:** `_delayed_obs` makes L3 data history-dependent. A current state variable and its delayed observation are not the same abstraction coordinate.
- **response_to_aid:** `Zone.last_response` becomes `Obs.response_to_aid` and is scored by policies. It is L2-relevant, not a reporting-only response metric.
- **neighbor_delta:** Written by `_update_neighbor_metrics` from neighbor state changes, then read by policy scoring and bad-consequence triggers. It is non-local and delayed, making it a major monotonicity risk.
