# B1.1 — Auxiliary-Calibration Robustness / Leakage Hardening Gate

**File:** `experiments/B/B1.1_Auxiliary-Calibration_Robustness_Leakage_Hardening_Gate.md`
**Task type:** bounded robustness / leakage-hardening experiment
**Status:** post-B1
**Allowed:** small Python implementation, synthetic robustness variants, controls, preregistered metrics, audit outputs
**Forbidden:** LLM training, internet data, natural language corpus training, Sanskrit parser, substrate/derivability/real-world-transfer claims

---

## 0. Immutable project goal

Keep this goal visible at every step:

> Train an LLM / learner so that its world-model is **derived**, not merely generalized from internet-like data.

Current refined hypothesis:

> The attainable form is “minimal empirical calibration, maximal derivational unfolding.”

B1 produced a narrow synthetic signal:

> In an additive toy-world `y = z_obj + bias_u + noise`, objective latent recovery failed without auxiliary variable and succeeded with auxiliary calibration anchors.

But B1 may be fragile because it used:

```text
one deterministic seed;
complete anchor overlaps;
additive observer bias;
a weak no-auxiliary baseline;
a deliberately symmetric confounding construction.
```

B1.1 exists to test whether the B1 signal survives robustness pressure.

---

## 1. Why B1.1 exists

B1 passed, but its claim strength is narrow:

```text
minimal auxiliary calibration can recover an objective latent scalar
in a bounded additive toy-world.
```

B1.1 must test whether that result was an artifact of:

```text
perfect complete anchors;
single seed;
pure additive bias;
weak no-aux baseline;
group/bias symmetry;
implicit leakage through auxiliary labels;
human-authored outcomes.
```

B1.1 does not attempt real-world disentanglement.
B1.1 does not attempt LLM training.
B1.1 does not claim substrate, derivability, grounding, or semantic boundary generation.

---

## 2. Gate question

Does the B1 auxiliary-identifiability signal survive a preregistered robustness suite?

Specifically:

```text
1. Does auxiliary calibration still recover z_obj across multiple seeds?
2. Does recovery survive sparse but connected anchor overlap?
3. Does recovery survive affine observer coloring, not just additive bias?
4. Do stronger no-auxiliary baselines still fail?
5. Do controls fail when anchors are missing, disconnected, shuffled, or random?
6. Does leakage audit still detect no hidden z_obj / final-label / outcome leakage?
```

## 7. Robustness variants

B1.1 must implement four primary robustness suites.

---

### 7.1 R1 — Multiseed additive robustness

Repeat B1-style additive world across at least:

```text
20 deterministic seeds
```

For each seed:

```text
y_i,u = z_obj_i + bias_u + noise
```

Use the same basic B1 confounding idea but randomize item variation and noise.

Required thresholds:

```text
mean_no_aux_abs_corr <= 0.35
mean_with_aux_corr >= 0.90
mean_improvement >= 0.55
at least 80% of seeds satisfy:
  no_aux_abs_corr <= 0.40
  with_aux_corr >= 0.85
```

Failure:

```text
B1.1-FAIL-MULTISEED-INSTABILITY
```

---

### 7.2 R2 — Sparse connected anchor robustness

Replace complete anchor overlap with sparse but connected anchor graph.

Examples:

```text
U0—U1 share anchors
U1—U2 share anchors
U2—U3 share anchors
```

No single anchor item needs to be seen by all observers, but the observer-overlap graph must be connected.

Learner must estimate relative biases by propagating pairwise anchor differences along the connected graph.

Required thresholds:

```text
sparse_anchor_with_aux_corr >= 0.85
sparse_anchor_improvement >= 0.50
```

Required negative control:

```text
disconnected_anchor_graph_corr <= 0.50
```

Failure:

```text
B1.1-FAIL-SPARSE-ANCHOR-ROBUSTNESS
```

---

### 7.3 R3 — Affine observer-coloring robustness

Use affine coloring:

```text
y_i,u = scale_u * z_obj_i + shift_u + noise
```

where each observer has:

```text
scale_u > 0
shift_u ∈ R
```

Learner may estimate affine calibration from anchors:

```text
z_est ≈ (y - estimated_shift_u) / estimated_scale_u
```

but must not use true `z_obj` labels during fitting.

Allowed anchor mechanism:

```text
same anchor item observed by multiple observers;
relative affine mapping between observers estimated from shared anchor y-values.
```

Use one reference observer coordinate. Evaluation may compare estimates to true `z_obj` up to affine transformation by Pearson correlation.

Required thresholds:

```text
affine_with_aux_corr >= 0.85
affine_no_aux_abs_corr <= 0.45
affine_improvement >= 0.40
```

Required negative control:

```text
affine_shuffled_aux_corr <= 0.55
```

Failure:

```text
B1.1-FAIL-AFFINE-BIAS-ROBUSTNESS
```

---

### 7.4 R4 — Stronger no-auxiliary baselines

Implement at least three no-auxiliary baselines:

```text
NO_AUX_RAW_RANK
NO_AUX_GLOBAL_STANDARDIZE
NO_AUX_QUANTILE_SEGMENT
```

Definitions:

```text
NO_AUX_RAW_RANK:
  rank-normalized y, as in B1.

NO_AUX_GLOBAL_STANDARDIZE:
  globally mean-center and scale y, then use standardized y.

NO_AUX_QUANTILE_SEGMENT:
  split y into four quantile bins and standardize within bins, without u.
```

These baselines must not use `u`, anchor identity, item_id grouping, true z_obj, or generated group labels.

Required threshold:

```text
max_no_aux_abs_corr <= 0.50
```

Failure:

```text
B1.1-FAIL-NO-AUX-ROBUSTNESS
```

---

## 8. Required controls

### C1 — Shuffled auxiliary

Shuffle `u` labels while preserving `y`.

Threshold:

```text
shuffled_aux_corr <= 0.50
```

### C2 — No anchors

Provide `u` but remove calibration anchors.

Threshold:

```text
no_anchor_corr <= 0.50
```

### C3 — Disconnected anchors

Provide sparse anchors whose observer-overlap graph is disconnected.

Threshold:

```text
disconnected_anchor_corr <= 0.50
```

### C4 — Random-world

Generate `y` independent of `z_obj`.

Threshold:

```text
random_world_corr <= 0.30
```

### C5 — Auxiliary leakage audit

Check:

```text
u does not uniquely identify item_id;
u does not directly encode exact z_obj;
anchors do not contain true z_obj labels for fit;
fit functions do not read z_obj;
true z_obj is used only after predictions are produced;
no human-authored final/outcome labels exist;
no seed-to-result lookup exists;
no variant-to-result lookup exists.
```

Any violation fails as:

```text
B1.1-FAIL-AUX-LEAKAGE
```

## 13. Failure conditions

Fail as `B1.1-FAIL-MULTISEED-INSTABILITY` if multiseed aggregate or seed fraction fails.

Fail as `B1.1-FAIL-SPARSE-ANCHOR-ROBUSTNESS` if connected sparse anchors fail or disconnected anchors pass.

Fail as `B1.1-FAIL-AFFINE-BIAS-ROBUSTNESS` if affine recovery fails or affine shuffled control passes.

Fail as `B1.1-FAIL-NO-AUX-ROBUSTNESS` if any stronger no-aux baseline exceeds threshold.

Fail as `B1.1-FAIL-CONTROL-LEAKAGE` if any negative control succeeds.

Fail as `B1.1-FAIL-AUX-LEAKAGE` if leakage audit finds leakage.

Fail as `B1.1-FAIL-HUMAN-AUTHORED-OUTCOMES` if human-authored final/outcome labels are used.

Fail as `B1.1-FAIL-REPEATS-S4-ACCOUNTING` if B1.1 only audits supplied fields and does not generate/recover from synthetic latent data.

Fail as `B1.1-INCONCLUSIVE` if results are mixed or thresholds are borderline.

Fail as `HALT-GOAL-DRIFT` if task becomes philosophy, literature review, demo packaging, unbounded ML, or LLM work.
