---

## 0. Immutable project goal

Keep this goal visible at every step:

> Train an LLM / learner so that its world-model is **derived**, not merely generalized from internet-like data.

Current honest status:

> B2 produced a valid bounded synthetic **relation-recovery** signal: auxiliary calibration recovered a generated 2D product-order relation from observer-colored coordinates, while no-auxiliary and broken-calibration controls failed.

But B2 is **not clean** as an order-dimension proxy result because its `classify_order_proxy` function used the generator `variant` label.

B2.1 exists to repair exactly that.

---

## 1. Why B2.1 exists

In B2, the primary relation recovery result is acceptable:

```text
no_aux_relation_f1 = 0.4738768131916582
with_aux_relation_f1 = 0.9965483444837431
relation_f1_improvement = 0.5226715312920849
```

But the toy order-dimension proxy is not clean because the classifier receives:

```python
variant: str
```

and then branches on generator labels:

```python
if variant == "chain":
    return "ORDER_1D"

if variant == "product2d":
    return "PRODUCT_2D"

if variant == "product3d":
    return "UNDERDIMENSIONED_FOR_2D"
```

This is a label/oracle leak for the dimension proxy.

B2.1 must repair this so that dimension classification is based only on:

```text
recovered coordinates
predicted relation
post-prediction evaluation metrics
relation shape statistics
```

and **not** on generator variant labels.

---

## 2. Gate question

Can B2 be patched so that:

```text
1. primary relation recovery remains valid;
2. toy order-dimension proxy no longer receives generator variant labels;
3. PRODUCT_2D / ORDER_1D / random / 3D controls are classified from relation geometry and metrics only;
4. 3D underdimensioning is detected through over-admission / precision failure, not through variant name;
5. static audit detects any future variant-conditioned dimension classification;
6. no new overclaim is introduced?
```

## 6. Required repair

### 6.1 Remove generator-label input from classifier

Patch the dimension proxy so that no function responsible for dimension classification receives:

```text
variant
dimension_label
true_dimension
generator_label
expected_classification
```

Specifically, replace:

```python
classify_order_proxy(..., variant: str)
```

with a label-free function such as:

```python
classify_order_proxy_label_free(
    relation_metric: dict[str, float],
    recovered_coords: dict[str, tuple[float, float]],
    predicted_relation: dict[tuple[str, str], bool] | None = None
) -> str
```

The exact signature may differ, but the classifier must not receive generator labels.

### 6.2 Allowed classifier inputs

The classifier may use only:

```text
recovered coordinate statistics
predicted relation statistics
post-prediction relation metrics
axis correlation
comparability density
precision
recall
F1
false-positive / over-admission rates
```

It may not use:

```text
variant
true dimension
generator class
control name
seed
expected result
human-authored classification label
```

### 6.3 Required label-free classification logic

Implement a bounded proxy, not general order-dimension recovery.

Allowed classifications:

```text
ORDER_1D
PRODUCT_2D
NOT_LOW_DIMENSIONAL_OR_INCONCLUSIVE
UNDERDIMENSIONED_FOR_2D
```

Recommended label-free rules:

```text
ORDER_1D:
  relation_f1 >= 0.95
  axis_corr_abs >= 0.95
  precision >= 0.95
  recall >= 0.95

PRODUCT_2D:
  relation_f1 >= 0.90
  precision >= 0.90
  recall >= 0.90
  axis_corr_abs <= 0.65
  0.10 <= comparability_density <= 0.45

UNDERDIMENSIONED_FOR_2D:
  recall >= 0.85
  precision <= 0.75
  false_positive_count is high relative to true_positive_count
  OR false_positive_overadmission_ratio >= 0.50

NOT_LOW_DIMENSIONAL_OR_INCONCLUSIVE:
  all other cases
```

The thresholds may be adjusted slightly if preregistered in the repair report, but they must remain label-free.

### 6.4 3D over-admission audit

For the 3D product-order control, B2.1 must not rely only on F1.

Add:

```text
three_d_precision
three_d_recall
three_d_false_positive_count
three_d_false_positive_overadmission_ratio = fp / max(tp, 1)
three_d_overadmission_detected
```

The 3D control passes only if:

```text
three_d_classification != PRODUCT_2D
three_d_f1 <= 0.80
three_d_overadmission_detected == true
```
