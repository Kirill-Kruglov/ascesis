# B2 — Relational Order-Dimension Recovery Gate

**File:** `experiments/B/B2_Relational_Order-Dimension_Recovery_Gate.md`
**Task type:** bounded synthetic relational-structure recovery experiment
**Status:** post-B1.1
**Allowed:** small Python implementation, synthetic relational world, preregistered metrics, controls, static/leakage audit outputs
**Forbidden:** LLM training, internet data, natural language corpus training, Sanskrit parser, substrate/derivability/real-world-transfer claims

---

## 0. Immutable project goal

Keep this goal visible at every step:

> Train an LLM / learner so that its world-model is **derived**, not merely generalized from internet-like data.

Current refined hypothesis:

> Minimal empirical calibration may allow recovery of invariant structure from colored observations.

B1/B1.1 showed a bounded scalar case:

```text id="oegjiz"
auxiliary calibration can recover latent scalar z_obj
from observer-colored observations
within additive/affine synthetic toy families.
```

B2 tests the next stricter step:

> Can auxiliary calibration recover an objective **relational structure** — a partial order generated by low-dimensional latent coordinates — rather than merely a scalar?

---

## 1. Why B2 exists

B1.1 is positive but still scalar. It shows:

```text id="a24vm2"
latent scalar + observer coloring + calibration anchors → scalar recovery
```

But the project intuition is about **world-structure**, not a single scalar.

B2 tests a minimal relational world:

```text id="f0jy74"
items have hidden 2D objective coordinates;
objective relation is coordinate-wise partial order;
observer/instrument classes distort coordinates;
auxiliary calibration should recover the relational order;
no-auxiliary and broken-calibration controls should fail.
```

This is the first step from:

```text id="xwz97m"
recovering a latent variable
```

toward:

```text id="coy8mo"
recovering a relational boundary / structure.
```

B2 does **not** claim exact general order-dimension recovery. It uses a bounded toy proxy:

> A relation is treated as 2D-product-order-like when it is well explained as the intersection of two recovered total coordinate orders and is not a 1D total order.

---

## 2. Gate question

Can a learner recover a hidden 2D product partial order from observer-colored coordinate observations:

```text id="8p8yby"
latent item coordinates: p_i = (x_i, y_i)
true relation: i <= j iff x_i <= x_j and y_i <= y_j
observer u sees colored coordinates:
  obs_i,u = affine_u(p_i) + noise
```

such that:

```text id="wvl59j"
without auxiliary calibration: relation recovery fails;
with auxiliary variable + calibration anchors: relation recovery succeeds;
toy order-dimension class is recovered as PRODUCT_2D;
controls reject shuffled u, missing anchors, disconnected anchors, random relations, and dimension overclaiming.
```

## 7. Synthetic relational toy-world

### 7.1 Latent objective structure

Generate `N` items with hidden coordinates:

```text id="g1n2qs"
p_i = (x_i, y_i)
```

where coordinates are deterministic pseudo-random values in a bounded range.

Define true partial order:

```text id="u81yw0"
i <= j iff x_i <= x_j and y_i <= y_j
```

Use strict margin to avoid near-ties:

```text id="rctabd"
i <= j iff x_i + margin <= x_j and y_i + margin <= y_j
```

Recommended:

```text id="x0lnqw"
N >= 60
margin = 0.03
```

The generated relation is the objective latent structure.

### 7.2 Observer / auxiliary classes

Use:

```text id="f05siq"
u ∈ {U0, U1, U2, U3}
```

Each observer has a coordinate-wise affine coloring:

```text id="8czw96"
obs_x = scale_x_u * x + shift_x_u + noise
obs_y = scale_y_u * y + shift_y_u + noise
```

with positive scales.

The learner may observe:

```text id="k0g2op"
item_id
u
obs_x
obs_y
is_anchor
anchor_identity / shared item identity
```

The learner must not observe:

```text id="nmh9hw"
true_x
true_y
true_relation
dimension_label
expected_relation
final_relation_status
```

### 7.3 Confounded allocation

Create a confounded observation allocation so raw no-auxiliary global coordinates are not directly comparable across observers.

Example:

```text id="o3kxkm"
U0 mostly observes low-left / lower-range items with positive shifts;
U1 observes lower-mid items;
U2 observes upper-mid items;
U3 observes high-right / upper-range items with negative shifts;
```

The allocation must be documented in `outputs/dataset_manifest.json`.

### 7.4 Calibration anchors

Use shared anchor items observed under multiple observers.

Primary with-aux condition should use enough connected anchor overlap to estimate observer transformations to a reference observer.

Required variants:

```text id="p48bdx"
complete anchors
sparse connected anchors
no anchors
disconnected anchors
shuffled auxiliary labels
```

## 8. Required learners

Implement at least two main learners and controls.

### 8.1 No-auxiliary learner

Input:

```text id="jzafzr"
obs_x, obs_y only
```

Forbidden:

```text id="58qkjf"
u
anchor identity
item_id grouping
true coordinates
true relation
```

Allowed strategy:

```text id="0lwpdo"
treat raw observed coordinates as a single global coordinate system;
predict i <= j iff obs_x_i <= obs_x_j and obs_y_i <= obs_y_j.
```

### 8.2 With-auxiliary calibration learner

Input:

```text id="yltyys"
obs_x, obs_y, u, anchor overlaps
```

Allowed strategy:

```text id="kczeai"
estimate per-observer affine maps to a reference observer using shared anchors;
transform all observations into reference coordinate frame;
predict relation by coordinate-wise order in calibrated coordinates.
```

Must not use true coordinates or true relation during fitting.

### 8.3 Toy order-dimension proxy

Implement a bounded proxy, not general exact order dimension.

Required classification:

```text id="gogmt1"
ORDER_1D
PRODUCT_2D
NOT_LOW_DIMENSIONAL_OR_INCONCLUSIVE
UNDERDIMENSIONED_FOR_2D
```

Rules:

```text id="gh8fuw"
ORDER_1D:
  relation is essentially a total order under one recovered coordinate,
  with relation F1 >= 0.95 on a generated 1D-chain control.

PRODUCT_2D:
  relation is well explained as intersection of two recovered coordinate orders,
  relation F1 >= 0.90,
  and relation is not total.

NOT_LOW_DIMENSIONAL_OR_INCONCLUSIVE:
  random/shuffled relation cannot be explained by recovered 1D/2D order above threshold.

UNDERDIMENSIONED_FOR_2D:
  3D product-order control cannot be explained well by 2D recovered coordinates.
```

Do not claim general mathematical order dimension outside this toy proxy.

## 10. Required controls

### C1 — Shuffled auxiliary

Shuffle `u` labels while preserving observations.

Expected:

```text id="fj0wuu"
relation recovery drops below threshold.
```

Threshold:

```text id="6xmpn4"
shuffled_aux_relation_f1 <= 0.65
```

### C2 — No anchors

Provide `u` but remove calibration anchors.

Threshold:

```text id="4s0ri3"
no_anchor_relation_f1 <= 0.65
```

### C3 — Disconnected anchors

Provide anchor overlap graph with disconnected observer components.

Threshold:

```text id="7j8fxr"
disconnected_anchor_relation_f1 <= 0.65
```

### C4 — Random relation / shuffled relation control

Generate a random relation or relation-shuffled world that is not generated by the 2D product order.

Expected:

```text id="4zn7nx"
2D product-order recovery should not explain it above threshold.
```

Threshold:

```text id="1q9hwi"
random_relation_2d_f1 <= 0.60
```

### C5 — 1D chain control

Generate a 1D ordered world.

Expected:

```text id="0kup7h"
dimension proxy should classify ORDER_1D, not PRODUCT_2D.
```

Threshold:

```text id="9nxvnj"
chain_control_f1 >= 0.95
```

### C6 — 3D product-order control

Generate hidden coordinates:

```text id="1u3dpn"
p_i = (x_i, y_i, z_i)
```

with true relation:

```text id="srjxzj"
i <= j iff all three coordinates are <=
```

But give only a 2D recovery mechanism.

Expected:

```text id="p82ksi"
2D proxy should not overclaim PRODUCT_2D success.
```

Threshold:

```text id="w2aay2"
three_d_control_2d_f1 <= 0.80
```

### C7 — Leakage audit

Check:

```text id="a9ucnu"
true coordinates are not used during fitting;
true relation matrix is not used during fitting;
u does not uniquely identify item_id;
u does not directly encode relation label;
anchors do not contain true coordinate labels;
fit functions do not read true coordinates/relation;
evaluation truth is used only after predictions are produced;
no human-authored final/outcome labels exist;
no seed-to-result lookup exists;
no variant-to-result lookup exists.
```

### C8 — Static audit

Run simple static scan over executable code files.

Scan for suspicious executable-code patterns:

```text id="u9g0io"
true_relation_by_item
relation_by_item
expected_relation
final_relation
dimension_label
true_dimension
status_by_seed
result_by_variant
lookup_relation
hardcoded_pass
```

The static audit may allow these strings in explicit forbidden-pattern lists, but not in executable lookup logic.

## 14. Failure conditions

Fail as `B2-FAIL-NO-AUX-RECOVERS` if no-auxiliary relation F1 exceeds threshold.

Fail as `B2-FAIL-WITH-AUX-NO-RELATION-RECOVERY` if with-auxiliary relation F1 fails threshold.

Fail as `B2-FAIL-DIMENSION-MISCLASSIFICATION` if PRODUCT_2D / ORDER_1D / random / 3D controls are misclassified.

Fail as `B2-FAIL-CONTROL-LEAKAGE` if shuffled/no-anchor/disconnected/random controls recover too well.

Fail as `B2-FAIL-RELATION-LABEL-LEAKAGE` if learner reads true relation labels during fitting.

Fail as `B2-FAIL-REPEATS-S4-ACCOUNTING` if B2 only audits supplied relation labels and does not recover generated structure.

Fail as `B2-INCONCLUSIVE` if results are mixed or thresholds are borderline.
