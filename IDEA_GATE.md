# The idea gate — what to ask before building

Distilled from the forge's most expensive lesson. In the philosophia line, about
four weeks of infrastructure (a governance harness, then a multi-arm learning
experiment) resolved to results already in the literature — Bartók et al. 2008 on
group-structured environments, grokking-acceleration work, process-vs-outcome
supervision — plus an elementary identifiability fact. None of it needed the
build to be known; all of it was caught by adversarial review *after* building.

The lesson is one process change: **run the checks that would kill or right-size
an idea before the infrastructure, not as a review after it.** Infrastructure is
the last thing a line builds, not the first.

A line answers these in writing before anything is built. A line that cannot pass
1–3 in a day is not ready to build.

1. **Identifiability / information.** Is the target even recoverable from the data
   or process proposed? Name what evidence must enter for it to be identifiable —
   a prior, labels, or observed interaction. If the data is distributionally
   invariant to the target, the *existence* question is closed a priori; do not
   build to "discover" it. (philosophia: a hidden quotient is not recoverable from
   quotient-independent syntax — a fact, not an experiment.)

2. **Tautology check.** Write the claim as one sentence. Would it also hold on
   random labels, or by definition? If it is near-analytic it is not a result.
   Find the empirical residue — a *measurable* quantity, an efficiency claim, a
   cost — or drop the claim. A compression event that appears on random labels is
   the failure mode the instrument exists to catch; do not publish one.

3. **Adversarial novelty scan.** Name the 3–5 nearest fields and search them, on a
   road that *wants* to find prior art (not the proposer). For each, state exactly
   what is already established and what — precisely — is left. "Ours" survives
   only what the scan cannot place.

4. **Falsifier and its price.** Register the kill before building. If the only
   decisive test needs a large programme, the idea is a programme, not a probe —
   decide that now, with eyes open, not after the sunk cost.

5. **Cheapest decisive measurement first.** What one profile, probe, or analytic
   argument most narrows the space? Prefer it to infrastructure. If the harness
   would outgrow the experiment, stop — that is the alarm that design-circling has
   started.

6. **Register vs earned.** Separate what can be claimed now (earned) from what is a
   registered design. Do not let a frame's beauty smuggle a registered thing into
   an observed one, or upgrade harness-valid to true.

Termination rule: **an experiment terminates on data; a design terminates on
consensus, which never comes.** Pour effort into the first. If a loop is
terminating on agreement rather than a number, it is circling.

Three deflations behind this gate, each caught late: a governance harness that was
over-engineering; a path-credit idea that was process supervision, already known;
a "manufacturable fraction" that was elementary identifiability. Moving 1–3 before
the build is what would have compressed each of them from weeks to days.
